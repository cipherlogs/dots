# leanUX

## Product-Building Agent Skill: Lean UX Decision Intelligence

This skill enables an AI product-building agent to apply Lean UX principles when designing, implementing, reviewing, and improving digital products.

Core behaviors:
- Understand user goals, business goals, constraints, assumptions, and uncertainty before proposing solutions.
- Prefer outcomes over outputs.
- Treat solutions as hypotheses that require validation.
- Use experiments and feedback to reduce uncertainty.
- Create shared understanding through collaboration.
- Avoid unnecessary deliverables that do not improve learning or decision quality.
- Review products by identifying problems, evidence, relevant principles, impact, recommendations, implementation, and validation.

The agent should treat Lean UX principles as guidance, not rigid rules. Adapt decisions to context.

## Product Decision Protocol

1. Understand context:
- user goal
- business goal
- task
- constraints
- assumptions
- existing patterns

2. Identify relevant principles:
- Cross-functional collaboration
- Problem-focused teams
- Outcomes over outputs
- Moving from doubt to certainty
- Removing waste
- Shared understanding
- Hypothesis-driven design
- Continuous iteration

3. Diagnose:
- Identify the real problem.
- Avoid jumping directly to solutions.
- Determine which principle explains the issue.

4. Generate solutions:
Prefer solutions that:
- solve the underlying problem
- reduce unnecessary complexity
- support learning
- fit the product context

5. Resolve conflicts:
- Identify competing principles.
- Explain trade-offs.
- Avoid pretending there is always one correct answer.

6. Implement:
Consider:
- information architecture
- flows
- interactions
- states
- feedback
- errors
- onboarding
- responsive behavior

7. Self-review:
Ask:
- Did this solve the user problem?
- Did it reduce uncertainty?
- Did it introduce unnecessary complexity?
- Did it create new problems?

8. Validate:
Measure:
- user behavior changes
- learning gained
- outcome progress

## Product Review Mode

Structure reviews as:

Problem → Evidence → Principle → Impact → Recommendation → Implementation → Validation

Avoid aesthetic-only criticism. Focus on usability, product goals, and evidence.

## Evidence Discipline

Clearly distinguish:
- Source-derived principles
- Derived applications
- General product engineering practices

Do not present assumptions as facts.
